# 本地维修 P2

> 历史阶段记录（2026-09-30）。后端能力保留，当前简化维修界面未提供本文所有独立诊断 / 升级入口，当前说明见 [产品功能](product.md) 与 [使用指南](usage.md)。下文验证仅属于当时版本。

承接 P0 的单一维修抽屉和 P1 的来源目录，本轮完成第一个纵向维修闭环：独立诊断、结构化工具、受审批配置维修、离线恢复、显式备用模型，以及一个安装来源明确的升级适配器。P1 代码回退标签为 `backup/post-product-p1-20260930`，运行资料与配置备份不属于 Git 回退。

## 使用与证据

维修抽屉中的本地诊断不需要选择模型，也不依赖 sidecar 启动。按用户选择检查受管配置及备份、进程名称 / PID、网关 TCP 端口和 PATH 中的 CLI 安装版本。记录状态、时间与分项证据，配置正确或端口可达均不冒充客户端调用成功。模型可使用 `diagnose_local` 组合分项检查；链路诊断限制在当前客户端与链路 / 维修模型所属来源，不接受任意文件路径、网络 URL 或 Shell 文本。

可选网络检查仅访问用户已保存且启用的 API Base URL，发送无凭据 HEAD，不跟随重定向、不关闭 TLS 验证、不调用付费模型。记录耗时和 HTTP 状态；无法取得响应时明确证据不足，不猜测是哪层超时，也不按网络失败判定模型不支持。

现有配置维修仍生成具体 JSON 方案，绑定配置 revision、接入记录与单次审批；写前备份，外部变更时拒绝覆盖，写后复读配置。沿用工作台的本地还原，sidecar 停止时也可恢复原接口。真实网关模型探测与真实目标客户端使用分别报告。本轮服务测试覆盖缺失配置 → 生成方案 → 人工批准 → 重写 → 配置复查及一次真实模拟上游网关请求。

关闭抽屉、切换导航不停止任务。独立停止按钮取消本地诊断 / 升级；会保留已取得的事实和已执行步骤，不宣称全部回滚。最多 50 条记录保存到 `local-maintenance.json`，重启时将未完成运行标为中断，不自动重试。损坏记录保留并提示，不覆盖它。记录不保存原始配置、进程参数、命令 stdout / stderr 或模型对话。

## 备用维修通道

用户明确选择已保存且密钥可读取的 Responses API 来源，通道偏好写入独立的 `maintenance-channel.json`，原 `maintenance-model.json` 保持 P0/P1 的字段格式，代码回退后仍可读取来源与模型。通道记录与模型不匹配或损坏时停用模型调用并提示重新选择，防止中断写入后默默回退。用户选择 `channel: direct`，不会自动降级到另一个账号。只支持原生 Responses，避免备用能力再次依赖 sidecar 的协议转换。

请求继续经过本机 `/v1` 的 Key 认证、模型 / 协议范围、预算预留、用量结算、上下文隔离与活动记录；只是此内部 Key 被允许在 sidecar 离线时调用它的原生 API。每次应用运行内，该来源 / 模型的内部 Key 累计上限为 32,000 tokens。普通客户端 Key 没有该例外，停用来源仍明确失败，未知用量继续阻止额度重放。

这是 sidecar 离线恢复能力，token-flow 主进程与本机权限服务仍需正常运行。整个应用打不开时，需先恢复应用或通过既有受保护配置备份手工处理；不宣称另有完全独立的桌面服务。

## 首个升级适配器

依据 [官方 Codex CLI 文档](https://learn.chatgpt.com/docs/codex/cli)核对 npm 安装通道。本轮仅支持 macOS / Linux 的 npm 全局 `@openai/codex` CLI：实际 PATH 可执行文件经 realpath 解析，其 package.json 名称 / 版本 / bin 路径与 `--version` 一致，且对应当前 npm 的全局目录。桌面应用、IDE 扩展、Homebrew、独立安装器、其他 CLI 与未知安装方式不猜命令。Windows 的 `.cmd` 需要额外执行策略，本轮拒绝套用 Unix 适配器。

方案查询官方 npm 注册表的 latest 稳定版本，保存确切版本、SHA-512 元数据、执行文件 / 参数 / cwd、时间 / 输出限额、安装指纹、配置 revision、影响和回退范围，有效期 10 分钟。用户人工确认才可执行；维修模型只有准备方案工具，模型审批策略不能授权软件升级。

执行前核对安装、配置、进程和更新元数据，再保存模式 0600 的配置与方案备份；开始安装前再次核对安装与空闲进程。使用具体版本与原 prefix 的 npm 全局安装命令，官方 registry 固定，不使用 sudo。npm 安装可能运行脚本，界面明确展示影响。进程与 token-flow 配置维修并发受控，发现运行中的 Codex 时拒绝升级。安装后的实际 CLI 版本与配置指纹必须符合方案；模型调用需另行验证，不以版本检查冒充通过。

有界执行器不启用 Shell，只接收后端配方生成的可执行文件与参数；过滤环境变量，不继承 API Key 等凭据；超时或输出超过上限会终止自己启动的进程组。它不是 OS 沙箱，安装脚本仍具有当前用户权限。中途失败可能已经修改软件，配置备份不保证软件降级或迁移回退；记录如实显示，未强制终止其他应用，也不放宽系统权限。
