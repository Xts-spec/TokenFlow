# 多 API 来源 P1

依据仓库外的 `token-flow-product-refactor-plan.md` v0.2，承接 P0 的工作台、模型来源、活动与维修抽屉。本轮实现 P1，不扩展系统命令执行、软件升级、离线维修或连接图。

P0 回退点：`backup/post-product-p0-20260930` → `d1260ad`。此标签只保存代码；运行数据迁移另有备份，不能将 Git 回退等同于资料目录还原。

## 完成的行为

- 多个独立来源：名称、HTTPS / 本机 HTTP 地址、协议、启停、多个上游模型 ID。同一协议可以保存多个来源。
- 支持 OpenAI Responses、OpenAI Chat Completions、Anthropic Messages；沿用当前 sidecar 的协议转换，不根据模型名字猜测协议。
- API Key 按来源和版本写入系统安全存储。渲染层只保留尚未提交的密码输入，保存后清空；列表和编辑接口均不返回已保存密钥或 CredentialRef。
- 模型列表读取与手工添加并存。保存来源可以没有模型；读取列表后需要确认并保存。最小验证一次只请求一个模型，结果按模型保存，并明确未验证工具、图片与客户端行为。
- 工作台、手动配置、维修与审批选择、Key 权限和活动共用账号 / API / 既有 Cursor SDK 来源的模型目录。模型路由 ID 为 `api-<sourceId>/<upstreamModel>`；界面在需要区分时显示来源名称和模型。
- 编辑列出相关 Agent、客户端 Key、维修 / 审批选择，要求确认影响。停用拒绝后续请求；删除有依赖的来源被服务端阻止，不自动切换来源或改写客户端。

## 路由与凭据边界

请求仍经过现有 `/v1` 入口的认证、模型 / 协议范围、预算预留、结算和活动记录。同协议调用保留原生 API 字段（含输出上限），经本机私有 relay 发送。需要转换协议时，sidecar 的模型别名保留来源归属，转换后的请求也仅发往该 relay；relay 才从系统安全存储读取对应上游密钥。

sidecar 配置不保存上游 API Key，只含本次进程的本机 relay 凭据。relay 绑定回环地址，检查自己的凭据、来源、模型、上游协议与固定路由，不接受任意目标 URL；只转发允许的协议头，禁止重定向，限制请求大小和空闲时间。上游错误使用分类信息，不回传原始错误正文。

来源保存后等待 sidecar 注册模型；同步失败会返回“来源已保存，路由待同步”，可重新保存或重启网关。选择器只展示已注册且密钥可读取的模型。API 来源的维修和审批经同一受限客户端 Key 入口调用并记录用量；内部 Key 在服务退出时撤销，异常退出留下的哈希记录可以在 Key 管理中移除。

API Responses 历史与压缩复用现有 GatewayContext，绑定客户端 Key、来源与模型，不允许跨来源续接。流中断记录为失败；缺失用量时有限额 Key 保持待核对状态，禁止盲目重放。

## 迁移与回退

桌面启动时将旧 OpenAI / Custom 单例复制为“迁移的 API 来源”，采用它原有的 Responses 协议。迁移前在资料目录的 `backups/api-sources-migration/` 保存旧 settings、存在时的来源目录和旧密钥密文。迁移标记与来源数据原子提交，避免重启重复导入；旧 settings 和密钥槽保留，旧任务仍可使用它们，不签发客户端 Key，不改写客户端配置。

迁移失败保留旧数据并提示，工作台仍能打开。回到 P0 时旧单例仍在；若需恢复 P1 来源目录，退出应用后使用迁移前的目录备份。API 来源编辑保留旧版本密文；删除只移除当前引用的密钥，不宣称清除所有恢复副本。运行数据不提交 Git。

无界面服务当前只有环境 / 内存密钥槽，没有持久化安全存储。本轮明确拒绝在该模式保存新 API 密钥，不以明文文件或重启即丢失的凭据冒充持久化来源。

`npm run test:api-sources` 使用真实 Electron、系统加密存储和模拟上游，验证添加两个来源、读取列表、逐模型成功 / 失败证据、Agent 接入、维修、受影响连接、停用、重启后凭据可用，以及 390 / 768 / 1320 宽度无横向溢出。截图位于忽略的 `artifacts/product-p1/`，全部使用测试数据。
