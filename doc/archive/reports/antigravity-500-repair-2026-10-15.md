# Antigravity 500 与账号目录修复验收（2026-10-15）

## 已定位的故障

用户报告的 `antigravity/gemini-2.5-flash` 500 对应生产日志 `error-v1-chat-completions-2026-10-15T200942-957fbae7.log`。原请求为流式 Chat Completions，4 条消息、4 个工具、7534 字节。上游记录没有 HTTP 响应头，错误为 `Post <URL>: EOF`，随后由网关包装为 HTTP 500。因此这次不是供应商返回的 HTTP 500，也不是模型已下架。日志不能进一步证明是服务端、链路还是失效空闲连接导致断开。

在 Antigravity 真实 executor 的普通、Claude 和流式请求入口，对响应头之前的 EOF 增加同请求一次重连。保留相同账号、模型、历史、请求身份与端点；等待 150ms，可取消。真实 HTTP 错误、收到响应头后的断流、用户取消均不重放；持续 EOF 最多两次尝试。推理可能已到达上游，不能承诺计费恰好一次；本层不会执行客户端工具。

长历史每次请求约 370KiB、约 9.4 万输入 token。上述 96 次恢复是**故障注入**，没有冒充 96 次自然故障。故障代理在转发前断开首次连接，第二次向实际供应商正常推理；不关闭 TLS 验证、不运行客户端工具、不轮换账号。测试代理仅由显式探针导入，生产程序不加载。

## 目录修复

- 所有授权来源取消内置静态列表作为账号权限兜底。静态信息只能补充已由官方目录确认的模型能力。
- 目录约每 30 秒刷新，平台刷新强制查询。短暂失败最多保留 15 分钟内验证过的目录并标记过期状态，超期隐藏。首次失败、明确空目录和不支持实时查询均不展示旧表。
- 修正桌面 1.5 秒超时先于上游目录 4 秒超时的问题；现在上游预算 8 秒，桌面管理请求 10 秒。
- WorkBuddy 明确的空 CLI 允许列表按零模型处理；不再扩大为全模型。
- Cursor 增加随账号轮询的目录更新和 15 分钟过期清除。
- xAI OAuth 目录复用推理端点及请求头，改用 CLI chat proxy。之前 API 产品端点的消费限制 403 不能代表 OAuth 模型权限；正确目录实测返回 `grok-4.7`。
- Antigravity 继续使用与推理一致的 daily 端点和项目，移除明确废弃型号、内部型号及实时目录没有的旧路由。账号、端点和 API/OAuth 模式变化会使缓存失效。

## 官方对话选择目录的进一步修正

用户追问 CLI 目录后，实时查询确认：`models` 包含兼容、补全、图片等用途；`agentModelSorts[].groups[].modelIds` 才是账号当前的对话选择名单。此前 17 个实时型号的展示仍过宽，现改为与此名单取交集，再排除废弃及内部型号，不合并 `commandModelIds`、图片或补全名单。空选择名单按零型号处理，字段缺失或损坏按目录失败处理，不回退全量表。

本机两份有效 Antigravity 账号最终均为：

- `gemini-3.8-flash-high`
- `gemini-3.8-flash-medium`
- `gemini-3.8-flash-low`
- `claude-sonnet-4-6`
- `claude-opus-4-6-thinking`
- `gpt-oss-120b-medium`

官方模型说明确认对话模型随套餐不同，其他辅助模型不属于用户可选推理模型：[Models](https://www.antigravity.google/docs/models/)。CLI 通过 `/model` 选择推理模型：[CLI reference](https://www.antigravity.google/docs/cli/reference/)。本机没有 `agy` 可执行文件；本次直接核对账号官方接口的对话选择数据，没有冒称运行过 CLI 的 `/model`。

新增选择目录回归先失败后通过；全账号真实查询再次完成。6 个是本次账号结果，不写死在程序中，未来随账号官方目录更新。
