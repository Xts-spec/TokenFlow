## FIX-001：恢复 Codex 官方登录可能覆盖并发配置修改

**位置：** [codex-accounts.ts](../../../packages/core/src/codex-accounts.ts)，`CodexAccounts.restore()`。

**复现与影响：** 恢复操作读取配置后，先写回 `auth.json`，再写回 `config.toml`。在两次写入之间，若 Codex 或编辑器修改配置（例如新增 `model_reasoning_effort="high"`），恢复操作仍使用之前的配置快照，导致新修改丢失。TokenFlow 内部锁不能阻止外部程序写入。

**修复建议：** 配置替换前重新检查内容或版本；发现外部修改时报告冲突，并仅回滚本次操作仍拥有的改动，保留外部修改及可恢复的备份。文件系统并发窗口也应纳入处理，不能仅依赖操作开始时的一次检查。

**验收标准：**

- 在授权文件写入后注入配置修改，恢复应报告冲突，外部新增字段保留。
- 冲突后授权与配置保持一致，或保留明确可恢复的状态；不得覆盖外部更新。
- 无并发修改时可正常恢复；同账号令牌刷新与重启后恢复场景仍通过。

**临时处理：** 恢复前完全退出 Codex，并停止编辑其配置文件。

## FIX-002：独立 ChatGPT 进程可能阻碍 Codex 自动重启

**2026-10-15 更新：** `AgentLifecycle` 根据 Info.plist 的 bundle ID 和主程序名检测、按同一实际路径退出和重新打开。模拟旧名称 Codex、独立 ChatGPT 共存、改名与用户安装目录均通过；Qoder 0.3.4、0.4.8 和 WorkBuddy 5.8.2 已实际重启。这里验证的是普通重启接口；`agentProcesses` / Codex 迁移的主动停止流程未在本项中扩大修改。

**位置：** [agent-lifecycle.ts](../../../packages/core/src/agent-lifecycle.ts)，Codex 的进程匹配与 `AgentLifecycle.restart()`。

**复现与影响：** 当前同时将 `Codex.app` 和 `ChatGPT.app` 路径判为 Codex 在运行，但退出命令只针对 `com.openai.codex`。当独立 ChatGPT 与 Codex 同时运行，Codex 退出后，独立 ChatGPT 仍会被计入检测，最终提示“尚未退出”，无法继续打开 Codex。

**修复建议：** 依据实际目标的应用标识或进程身份统一检测、退出与启动。部分 Codex 安装使用 `ChatGPT.app` 旧名称，不能直接删除该路径兼容；应区分旧名称的 Codex 与独立 ChatGPT。

**验收标准：**

- Codex 退出后，即使独立 ChatGPT 仍在运行，也能继续重新打开 Codex。
- 应用名为 `ChatGPT.app`、实际标识为 `com.openai.codex` 的安装仍能识别和重启。
- 用户取消退出或存在保存提示时，仍正确提示，不强制结束进程。

**临时处理：** 手动完全退出并重新打开 Codex。

## FIX-003：WorkBuddy 缺失额度数据被解释为无活跃限制

**2026-10-15 更新：** 当前代码对缺失资源包、空列表输出“额度暂未提供”，不再解释为无限制；`tests/quota.test.ts` 覆盖空列表、空 data、有效套餐与余额。真实账号的额度限制仍然生效，429 不属于已消除的问题。

**位置：** [quota/workbuddy.ts](../../../packages/core/src/quota/workbuddy.ts)，`workbuddyQuota.fetch()` 的无有效数据分支。

**复现与影响：** 额度接口返回 HTTP 200 和 `{}`，或资源包字段缺失、无有效数据时，会显示“当前无活跃计费资源包限制”。接口成功不等于额度已查明，缺失数据也不能证明账号没有额度限制，容易误导用户选择来源。

**修复建议：** 区分缺失或无效响应、明确空资源包列表、有效额度数据。未知情况显示“额度暂未提供”或“未知”；没有明确依据时不推断额度无限或没有限制。额度查询异常不应删除已保存的授权。

**验收标准：**

- 覆盖 `{}`、字段缺失、字段格式无效和明确空资源包列表，均不误报无限或无约束额度。
- 有效套餐的零余额与正余额能正确显示，现有套餐解析不受影响。
- 查询失败或额度未知时保留账号授权，并提供可理解的状态提示。

**临时处理：** 数据缺失时将额度视为未知，在来源官方界面核对。
