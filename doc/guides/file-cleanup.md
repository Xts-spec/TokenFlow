# 文件清理

在侧栏 **文件清理** 点击 **开始扫描**。扫描只读取文件元数据，检查当前用户下的已知 Agent、应用和开发工具位置，不对整个磁盘进行无差别遍历。

- **可重建缓存**：npm / npx 下载、Gradle 缓存、Qoder 共享客户端缓存，以及应用的 Cache、Code Cache、GPUCache 等明确子目录。清理前关闭相关应用与安装任务，再次使用可能需要联网下载。
- **需要确认**：浏览器和 Agent 运行时、Claude 虚拟机镜像、TokenFlow 会话迁移备份、部分安装包和工具链、添加项目目录后找到的 node_modules。占用与最近修改时间不能证明文件已经无用，逐项核对清理影响。
- **受保护数据**：Codex 会话、Claude / Gemini / OpenClaw 资料、编辑器用户设置及 pnpm 共享存储等，只展示占用。pnpm 建议通过官方的 `pnpm store prune` 清理未引用包，不整体移走共享存储。[pnpm 文档](https://pnpm.io/cli/store)

在 **扫描范围与项目目录** 中添加具体项目目录后重新扫描，可查找最多 6 层内的 node_modules。不会深入隐藏目录、依赖目录、构建输出或系统应用目录；当前 TokenFlow 工作目录所用的项目依赖受到保护。项目目录只保留在本次运行期间。

扫描结果支持风险分类、文件类别和名称 / 路径搜索，默认不勾选任何项目。选择 **检查并清理** 后会列出具体路径、大小和影响；确认相关应用已关闭，涉及「需要确认」项目时还需单独确认其影响。

桌面版通过系统废纸篓 / 回收站处理文件，未提供永久删除或自动清空入口。可在清空前到系统废纸篓手动恢复；**移入废纸篓不等于已经释放磁盘空间**。[Electron 文档](https://www.electronjs.org/docs/latest/api/shell#shelltrashitempath)

清理仅接受当前扫描生成的项目 ID，结果在 30 分钟后失效。处理前重新校验整个目录的元数据；遇到符号链接路径、权限不足、未完整统计或文件变化时拒绝清理，并逐项显示原因。文件逻辑大小与实际可释放空间可能因硬链接、稀疏文件或系统快照而不同。

扫描可中途停止。单个目录、项目查找范围与整次扫描均有上限；未完整统计的结果只能查看。浏览器 / 无桌面能力的服务只提供只读扫描。
