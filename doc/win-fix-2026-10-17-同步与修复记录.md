# win-fix 同步与修复记录（2026-10-17）

本文记录 win-fix 分支同步 origin/main 之后，Windows 实机验收发现并修复的全部问题，以及打包链路的已知坑与规避方法。mac 侧交接背景见 [待修复的问题win兼容.md](./待修复的问题win兼容.md)。

## 一、分支同步

- 以 `origin/main`（0f214cd，含 af289621）为产品基准合入 win-fix（合并提交 `b01c1ab`）：界面、交互、用量对账以 main 为主。
- 冲突解决（`agent-installation.ts`）：保留 win-fix 的 `windowsRegistryApp` 注册表发现，采用 main 扩展的 `workbuddy-ai` 桌面检测签名。
- `cliproxy.ts` 自动合并正确：win-fix 的 `process.execPath` sidecar 启动保留，main 的 `nativeUsageAccounts()` 历史归属合入。

### DeepSeek 欢迎页机制备注

- Harness 凭据解析优先级：**继承环境变量 > 托管 `.credentials.yaml` > 主目录 `.env` 兜底**（官方文档明确）。
- `.env` 对用户手动启动同样生效；实测写入后 CDP 仅见 `dsh-app://app/` 主窗口，欢迎窗口不再出现。
- 副作用说明：`DEEPSEEK_API_KEY` 指向 TokenFlow 网关 Key，在 Harness 内选官方 DeepSeek 直连模型会鉴权失败，属预期；恢复原配置后自动清除。

## 四、打包链路已知坑与规避

| 坑 | 规避 |
|---|---|
| electron-builder 26 自带下载器直连 GitHub 拉 Electron zip，TLS 中断（挂代理也断） | `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/` |
| 宿主 HTTP_PROXY 会导致 sdk tgz 下载截断 | 打包命令清除 `HTTP_PROXY/HTTPS_PROXY` 与 `NODE_OPTIONS` |
| `release*/win-unpacked.tmp` 残留被杀软锁死（EBUSY，连改名都拒绝） | 不硬刚；换新输出目录或等句柄释放后手动删 |
| 本机 Electron GUI 启动必须 | `--no-sandbox --in-process-gpu --disable-gpu --disable-dev-shm-usage --use-angle=swiftshader`，且清除 `ELECTRON_RUN_AS_NODE` |
| 会话内派生的 GUI 进程随命令结束被回收 | 用常驻后台方式启动验证 |

## 五、遗留事项

- 旧打包目录清理后有约 440MB 杀软锁定残留（各 release 目录内 `app.asar`/`default_app.asar`），句柄释放后可手动删除。
- 全量测试套件在打包版占用 9527 期间跑过一次（79 失败，高于基线 45），需在净环境下复跑确认；`agent-installation.test.ts` 有 5 个 win32 预存在失败（`automatic` 恒 false），与合并无关。
- 交接文档中的 Windows 实机验收清单仍有未完成项：备份/恢复对话、CC Switch 重新应用、官方/自定义并存等。
