# 本机历史用量日志导入方案

状态：待实现，先保留方案。

来源：dev-debug 工作树中尚未提交的 USAGE-006 方案，保存于 2026-10-21。这里讨论的是本机客户端用量日志导入，不是对话交接功能。

尚未写代码。现在启动后会直接扫描客户端用量日志并写入 `local-usage-index.json`，和钥匙串是否允许无关。TokenFlow 自己的请求记在资料目录的 `usage-ledger.json`，保留 180 天。下面按这个边界实现，不要把两份记录合成一次选择。

启动时在现有「读取本地登录」之后单独再问一次，两题互不影响：

- 钥匙串沿用现在的规则：只有允许并成功读取才记住；「暂不读取」、Escape 或关掉窗口都不写入记住文件，下次仍问。
- 历史日志只在用户点了按钮后写入 `local-usage-history.json`。关掉窗口、脚本失败或还停在钥匙串那一题时，不得落成「从现在开始」。Escape 不要偷偷当成已选择。
- 两个答案都记住。「导入已有记录」和「从现在开始」之后都不再问。菜单「下次启动重新选择登录读取」只重置钥匙串，不重置历史选择；若要重选，另给入口，不能靠删一半文件。

选择的效果：

- **导入已有记录**：扫描客户端已有日志，写入索引，之后继续追加。
- **从现在开始**：把选择时刻写成起点。这个时刻之前的样本不写入 `local-usage-index.json`；该时刻之后的本机用量照常写入。同一天里、点击之前的记录也不写入，起点是时刻而不是自然日。
- 两种选择都继续扫描。不要因为没导入历史就把之后的本机记录停掉。
- `usage-ledger.json` 始终只追加 TokenFlow 自己的请求。历史选择不读、不改、不删它。已经记下的用量在重装或替换应用后仍在，因为文件在资料目录，不在应用包里。删掉资料目录才会一起丢掉。
- 走 TokenFlow 的同一条请求若也出现在客户端日志里，继续用现有路由标记和响应指纹排除，不在索引里再加一次。

索引按文件戳跳过未改动日志。从「从现在开始」改回「导入已有记录」时，必须让这些文件重新解析；只删选择文件不够，旧样本不会回来。改回之前不要提供会把索引写残的切换。

验收：

- [ ] 第一次选导入后，已有本机日志进入总览，下次启动不再询问。
- [ ] 第一次选从现在开始后，起点前的日志不进索引，起点后的本机用量和账本都继续增加，下次不再询问。
- [ ] 允许钥匙串同时不导入历史、暂不读取钥匙串同时导入历史，两种组合都成立。
- [ ] 关掉窗口或在钥匙串题上离开，不产生 `local-usage-history.json`。
- [ ] 历史选择和重装应用都不改变 `usage-ledger.json` 里已有行。
- [ ] 经 TokenFlow 的请求在导入本机日志后不重复累计。
