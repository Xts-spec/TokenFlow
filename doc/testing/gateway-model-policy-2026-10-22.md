# 模型等待与压缩策略（2026-10-22）

用户澄清允许保留合理的自动压缩触发，要求去掉会误伤正常体验的额外限制，并删除 WorkBuddy 本地等待计时。完全删除阈值的实验没有发布，本次恢复客户端自动压缩触发。

## Codex

来源提供 `contextWindow` 时采用该值；仅 `codex/` 官方账号路线可以使用本机官方 `models_cache.json`，同名第三方 API 不借用官方容量。软触发取已知窗口的 80%：当前 Luna/Astra 的 272000 对应 217600，Sol 的 500000 对应 400000。较小的真实容量同样按比例计算，不强行设较大下限。

容量未知时采用 128000 Token 兼容默认，替代原 65536。它不是厂商窗口声明，不能保证每个未公布容量的来源都能接受 128000 输入；获得来源容量后使用真实信息。仍不声明 `context_window`，以避免重现安装版 Codex 切换到较小窗口时用旧模型向新网关压缩的 403。

继续使用 `model_auto_compact_token_limit_scope=total`：缓存命中仍属于当前输入、占用窗口；不是把每轮账单累计相加。首次既有的 256 KiB 整理目标、容量/时间权重并行、固定分组、摘要复用及后续仅由 Codex 触发不变。没有新增正文拒绝、截断或服务端逐轮压缩。

服务启动会更新应用生成的 `agent-backups/codex-models-*.json` 中的触发值，保留模型列表、显示名、路由、授权及用户 config.toml 字节。单个旧目录无法更新时记录警告，不拒绝推理请求。新接入同时携带来源容量。目录由 Codex 启动时读取，已运行的 Codex 需要下次启动才能读到新值；本次不重启 Codex。

## WorkBuddy 与 SSE

删除本地 240 秒总计时、SDK 包装层 60 秒无模型进展计时、`SDKIdleError` 和由此触发的一次静默重试。正常完成、来源/官方 SDK 错误、断流、用户取消仍正常传递。没有修改官方 SDK 自身默认设置。完整工具提案交回客户端、来源身份/区域绑定和清理保留；响应结束或取消后的 8 秒子进程清理兜底不是生成等待上限。

SSE 行解析器保持原实现。上游通常把流式输出写成许多数据行，网络层再把字节分成大小不定的片段；解析器拼合片段后处理完整行，不会把超大 JSON 行自动拆成几个等价事件。长对话不按整段历史或整篇回答总长度触发行上限，但一个非常大的工具参数或内容块仍可能超过 1/50 MiB。不能承诺长会话绝无此风险。
