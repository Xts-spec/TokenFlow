# 网关等待策略核查（2026-10-21）

## 本次变更范围

按用户明确提出的要求，删除通用生成链路的 300 秒无数据计时和 600 秒单请求总时限。删除计时器实现及由它们合成的 504 错误分支，不把超时数字换成更大数值。本机、LAN、首次并行摘要、后续显式摘要、API 私有中转共用新的取消传播边界。

Node fetch 自身有响应头和正文等待计时。生成请求通过当前全局网络 dispatcher 发送，单次 dispatch 设置 `headersTimeout:0, bodyTimeout:0`，避免外层计时去掉后仍由 HTTP 客户端截断。没有新建绕开用户代理的直连连接池；管理、授权和模型列表请求的独立超时没有改动。DNS、建立连接、TLS 等网络层故障以及来源 SDK 自身行为仍可能返回错误，本次不声称取消所有层级的超时。

客户端断开、主动取消仍会取消源请求和正在执行的摘要；完成一个并行摘要会解除它自己的取消监听，不影响其他摘要。上游 HTTP 状态、上下文错误和响应流中断继续按原链路处理。没有增加裁剪、请求大小检查或新的自动重试。

上游明确拒绝时通常返回 HTTP/SSE 错误；但半开连接或服务一直无响应不保证主动返回错误码。本策略允许它继续等待，用户或客户端可以取消，不由网关另设倒计时。

## 20 秒 / 35 秒只是隔离测试

上一轮的测试启动一个独立临时 HOME 的安装版 Codex，只在该子进程命令行传入 `model_providers.token_flow.stream_idle_timeout_ms=20000`，并让合成摘要响应故意等待 35000 毫秒。这样可以在几十秒内复现“等待时间短于摘要生成时间”，验证注释心跳失败而有效 `response.in_progress` 事件能维持原生客户端连接。

该测试没有给真实用户配置写入 20 秒，也没有让真实来源固定延迟 35 秒。它不是 Codex 原有的 20 秒设置，更不是新生产限制。OpenAI Docs 的[配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)说明流空闲等待默认 300000 毫秒、流重试默认 5 次；网关接入生成器未覆盖这两个值，本次也不修改用户 Codex 配置。
