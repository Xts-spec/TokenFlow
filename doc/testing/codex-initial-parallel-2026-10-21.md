# 首次历史并行压缩与官方摘要复用 — 2026-10-21

## 行为

仅管理的 Codex 会话在本次接入首次整理历史时使用新策略，包含旧用量不足、由首次普通续聊引导整理，以及 Codex 在首次接触时主动发送 compaction_trigger 或 /responses/compact 两种入口。切换时仍只备份、切换来源。先匹配已保存历史前缀和摘要，只有未覆盖部分进入首次整理。

优先使用来源模型元数据；对于 codex/ 账号路线，还可以读取该 Codex 配置目录的 models_cache.json 中匹配型号的 context_window。不同来源的同名模型不会套用官方容量。本次 Luna 读到 272000 Token，未使用它的 max_context_window 扩展容量。缺少元数据时从 512 KiB 请求规划起步，通过真实上游容量拒绝细分，不宣称这是模型的真实窗口。

首次规划以每 Token 约 2 字节估算输入，使用声明窗口的 80% 规划分块，给指令和输出留空间；这不是请求拒绝阈值，也不是文本裁剪。模型真实返回上下文超限时递归拆分原文，每次严格减少子块，不丢 Unicode 字符、不制造空块。时间顺序分为较早 50%、中间 30%、较近 20%；较早块更大且摘要偏重结果，较近块更小且保留具体工作状态，任何时间段的有效约束、决定、待办都要求保留。当前指令、最近必要交互以及已有检查点仍优先保留。

首次默认四个工作请求并行执行，结果按原历史顺序合并。Cursor 的现有 SDK 每账号只允许一次生成，故该来源排队，避免人为触发它已有的 cursor_busy。后续自动增长不由网关触发压缩；Codex 明确发起的后续压缩沿用串行路径，不套用首次并行调度。

每个完成的分块即时保存为加密缓存；失败后等待已在途工作结束并保存、结算已知用量，重启后复用完成块。首次整个任务不再被 600 秒累计倒计时终止；每个实际上游请求独立沿用原有 300 秒无数据、600 秒单请求时限。首次结束后恢复普通回答计时。客户端取消会传递给工作请求。首次 SSE 每 15 秒发送注释保活，不伪造模型文字或用量；失败发出明确 response.failed，不把半成品当成功摘要。

没有恢复 1 KiB 摘录、工具输出 10000 字节策略、摘要 max_output_tokens 或“摘要必须变短”的拒绝。48 KiB 保留在后续客户端主动压缩的既有串行路径，此次仅改变首次整理。

## 真实 Luna 实测

隔离 HOME 中运行安装版 Codex 0.163.0-alpha.11，构造十二个约 1 MiB 的完整合成历史批次，历史合计 **12,666,536 字节（12.67 MB）**，最初没有摘要。调用已授权的 codex/gpt-6-luna。凭证仅用于本地来源桥接，记录不含凭证和用户对话正文。

| 项目 | 实测 |
|---|---:|
| 首次完整历史压缩 | 122.916 秒 |
| 首次回答全程 | 126.586 秒 |
| 重启后复用并回答 | 4.172 秒 |
| 后续显式触发的增量压缩 | 36.327 秒 |
| 增量压缩端到端 | 36.479 秒 |

首次 39 个原文分块和 3 个合并请求，共 42 次摘要请求，实际累计输入 4,785,200 Token（合成随机标识内容较密集），输出 12,016 Token。各请求时长累计 453.884 秒，并行后整个压缩 122.916 秒。所有原文分块均发送给 Luna，未发生上游上下文超限；最早随机校验要求保留。对比上一候选版的 48 KiB 串行方式：15 分钟仍未完成，本次完成并回答。

首次回答的计费 usage 包含摘要调用，原生 Codex 重启时因其记录的用量主动请求过一次远程压缩；该过程复用了已存摘要，没有新增摘要模型调用。后续增量测试加入约 300 KB 合成工作记录，显式压缩产生 5 次串行摘要调用。测试没有声称重启后客户端绝不触发压缩，也没有把合成上游毫秒耗时当 Luna 耗时。

另用安装版 Codex + 合成上游验证旧用量已知为 150k、客户端先发 compaction_trigger 的首次场景。发现并修复旧历史以巨大已完成助手消息结尾时仍保留最后整条消息的问题：首次整理允许将已完成末条消息送去摘要，保留当前用户要求和未完成工具交换，不截断消息。该场景现在可完整压缩、续聊并在重启后复用。

## 官方链路复用

网关 tfctx1 密文不是官方加密检查点，不能原样提交给官方。已有 prepareOfficial 将它还原为已保存的文字摘要与必要近期消息，写入原生可读 replacement_history；不需要重做模型摘要，也不需要恢复完整旧历史来替代有效摘要。官方后续压缩仍由 Codex 决定。

安装版 Codex 隔离会话验证了网关→原生提供商→网关往返、工具调用绑定、重复客户端压缩与摘要保留。原生提供商恢复后的请求另外交给真实授权 Luna，模型成功从明文检查点读出最早任务标记，响应 4.387 秒。真实调用经本机凭证桥接到 Luna，并非切换用户当前 Codex 登录；没有宣称网关密文已被官方识别。
