# Codex 网关长会话压缩

## 官方会话首次切换

切换时只备份配置和会话、迁移路由，不调用模型，也不预先压缩所有历史。第一次继续对话由 Codex 发出请求，TokenFlow 在网关入口恢复可读历史，调用这次选择的来源和模型生成摘要，然后继续正式回答。后续超出预算时走同一条压缩路径。备份成功不代表摘要已经生成；首次等待包含摘要耗时，摘要失败时保留原始历史。

官方的 `compaction.encrypted_content` 不是其他模型可读的摘要。TokenFlow 只在托管的 Codex 接入中，从本机 rollout 找到匹配的压缩条目，恢复它覆盖的可读历史，再生成网关检查点。不会把官方密文当作正文，也不会修改原始 rollout。

rollout 文件大小不等于请求 Token 数：文件还包含事件、用量和重复记录。验证样本为本项目的一份 12,277,233 字节 rollout，恢复后的请求历史约 4.7 MB。普通导出 Key 不能调用这条本机恢复路径。

恢复扫描沿用原有安全界限：单个 rollout 最多 64 MiB，可恢复历史最多 16 MiB。超过界限或找不到明确历史时停止，要求从原来源生成可读交接摘要，不会猜测官方密文内容。

## 压缩策略与预算

- 摘要使用当前授权来源和模型，读取 Responses SSE；正文可来自完整终态、完成条目或文本增量。推理增量只表示进度，不作为摘要正文；缺少终态、空正文、工具调用或未完成摘要均拒绝替换历史。
- 旧工具参数、工具结果和助手工作保留有明确省略标记的摘录。工具结果兼容字符串和内容数组；旧二进制附件只保留占位说明。用户文字与指令提供给摘要模型；当前用户消息、指令以及最近完整工具交换原样保留。省略内容需要时回看原会话或重新读取文件。
- 摘要按最多 48 KiB UTF-8 文本分块，每次最多 32 次模型调用。小尾块的摘要允许略长，但每轮合并后的摘要必须整体缩小。压缩结果按 **JSON 序列化后的真实大小** 检查；超过预算继续归并，不能缩小时停止。预计调用超过上限则在第一次付费请求前拒绝。
- 当前来源目录缺少经过验证的 tokenizer 和逐模型窗口元数据，因此采用保守回退：历史缩减基准为 128 KiB、软触发基准为 96 KiB；实际目标至少容纳固定工具定义、系统/开发者指令和最新用户消息，再保留 32 KiB 历史空间。自动触发按可缩减历史计算，至少累积 16 KiB。新对话不会仅因固定配置大而压缩或报 413。该目标不是模型上下文硬上限，上游仍可能拒绝其真实窗口放不下的请求；网关 16 MiB 请求安全上限保留。
- 静态工具定义不单独触发重复压缩；刚压缩过的检查点需要累积足够旧工作才再次触发。Codex 的网关模型目录提供 131072 Token 窗口、65536 自动压缩阈值作为回退，网关历史缩减目标仍独立生效。
- 上游真实响应块刷新 300 秒空闲计时，同时保留 600 秒请求总时限，覆盖本次摘要与回答。摘要请求采用流式传输；上游是否实际逐块返回仍取决于来源。Cursor SDK 当前等到运行完成才转换为响应事件，期间仍受空闲时限约束。

## 失败、复用与用量

摘要语义失败返回 HTTP 422 与具体 `compaction_*` 错误码，避免客户端按通用 502 反复自动付费。相同空摘要、未完成或无效摘要有短暂冷却；连接中断允许用户修复来源后重新尝试。

成功摘要按网关 Key、来源、模型、摘要版本和分块内容隔离，使用本机密钥加密。托管 Codex 即使上游 `store:false` 仍保留本机派生摘要，以便重启后续做；普通导出 Key 的 `store:false` 摘要只在内存复用。持久缓存保留最多约 512 块、7 天，启动及定期清理；内存最多 256 块。缓存写入失败不会丢弃已经生成的可用摘要。原始会话、最近工具交换不会被该清理删除。

正式回答失败或流中断时，仍结算已经确认的摘要消耗。缺失部分用量标记为未结算，保留确认部分作为下界；未知缓存不记成零。Responses 聚合用量中的 `token_flow_unmetered:true` 表示仍有未报告部分。调用详情展示压缩大小、调用/复用块数、耗时及输入、输出、缓存、推理 Token；摘要用量已计入请求总量，不能重复相加。

## 续聊与切回官方

不增加摘要正文展示或额外正文查看记录。安装版 Codex 主动压缩时，已验证会发送 `item/started`、`item/completed`，条目类型为 `contextCompaction`；沿用客户端原生状态。网关首次接手历史时的内部压缩暂不增加自定义进度事件或额外聊天回复。

网关继续多轮时，会展开最近检查点并追加后续消息，累积到预算后再次压缩「已有摘要＋后续工作」。当前指令、最新用户消息和最近完整工具交换继续保留；不会每一轮重新扫描和发送全部原始 rollout。

从 TokenFlow 切回官方前，若需要改写会话则必须退出 Codex。程序会先备份，再将最新 TokenFlow 加密检查点展开成可读摘要和近期上下文、清理网关生成的异源条目标识，保留检查点之后的消息和工具配对；切换本身不调用摘要模型。切回官方后并不会恢复已经在摘要中省略的旧正文，需要时仍应回看原会话备份。后续压缩由官方 Codex 链路负责。

## 回归与真实验证

```sh
npx vitest run tests/context-summary.test.ts tests/gateway-compaction-regression.test.ts tests/gateway-context.test.ts tests/codex-context.test.ts tests/gateway-context-service.test.ts tests/gateway-traces.test.ts tests/upstream-idle.test.ts
npx tsx scripts/context-codex-smoke.ts qoder/fixture
npx tsx scripts/codex-context-migration-smoke.mjs /path/to/codex --long-recovery
npx tsx scripts/codex-context-migration-smoke.mjs /path/to/codex --long-recovery --repeat-gateway
npx tsx scripts/codex-long-context-replay.ts --rollout=/absolute/path/to/rollout.jsonl
```

前两种 smoke 使用实际安装的 Codex 与合成来源，不消耗模型额度。rollout 回放默认也使用合成来源；它复制原文件到临时目录，并在结束前校验原文件哈希。

真实模型验证必须显式传 `--live --model=qoder/... --max-calls=N`，会消耗所选来源额度。脚本从本机 sidecar 配置读取凭据，不打印凭据；发送前屏蔽常见令牌字段。可用 `--cache-root=/private/path` 保留加密摘要跨次复用，临时 rollout 副本仍会删除。输出仅记录请求大小、调用次数、用量和受限的回答片段。

Cursor 使用 `--live --model=cursor/grok-4.5 --cursor-credential-stdin --max-calls=32`，通过私有管道提供已授权账号的凭据 JSON；凭据不放入命令参数、日志或文件，脚本不会创建或更新授权。先检查真实模型目录，再调用项目中的 CursorProvider。`--first-checkpoint` 可单独回放第一份官方检查点及其后第一个完整工具交换；默认回放最新窗口，输出明确标记所测窗口。

真实回放调用 `GatewayContext` 与已运行的 sidecar，验证实际历史恢复和模型摘要；实际 Codex 协议及 HTTP 用量结算分别由安装版 smoke 和服务集成测试覆盖。真实来源未完整回答时，不得将合成回归通过表述为真实长会话验证通过。

`--repeat-gateway` 验证官方会话→网关连续三轮（实际触发多次压缩）→另一网关模型→切回官方→更换 Key 再切换。安装版 Codex 配合合成来源的实测完成 50 次 HTTP 请求、4 次网关摘要，确认跨压缩后的用户约束、工具结果和可读摘要延续；同时校验网关阶段多次原生压缩开始/完成事件配对。该测试不使用真实官方账号额度，不能表述为真实官方来源端到端通过。

### 2026-10-19 Cursor Grok 4.5 实测

使用已有授权，运行前检查真实目录和额度；没有新建授权，也没有修改本机 Codex 配置或原始会话。以下大小是 GatewayContext 输入的 JSON 字节数，Cursor SDK 的传输包装可能额外增加输入。

| 场景 | 历史 → 压缩结果 | 实际新增调用 | 结果 |
| --- | --- | --- | --- |
| 第一份官方检查点，无摘要缓存 | 768,326 → 120,878 字节 | 4 次摘要 + 1 次回答 | 94.9 秒，返回目标、约束、下一步，原文件哈希不变 |
| 最新窗口，失败后复用成功分块继续 | 4,715,151 → 94,582 字节 | 复用 19 块，新增 3 次摘要 + 1 次回答 | 81.0 秒，完成回答，原文件哈希不变 |

首次最新窗口回放发现了小尾块问题：前 19 块成功，最后约 1 KiB 分块因摘要略长被逐块收缩校验拒绝，尚未进入正式回答。随后补了回归，改为检查整轮是否收缩；重测沿用加密缓存续做，没有重新生成前 19 块。整轮或最终上下文不能缩小时，会失效相应摘要并短暂冷却，避免同一无效摘要永久阻塞手动重试。

首次失败回放已确认消耗 394,986 输入 / 24,700 输出 Token；续做本次总量为 61,421 输入 / 3,757 输出，其中缓存读取 3,584。第一份检查点测试总量为 105,070 输入 / 4,836 输出，其中缓存读取 4,480。这些都是上游返回的用量；没有把推理未拆分部分记为零。首次迁移有实际成本，摘要缓存复用不等于上游输入缓存命中，也不能承诺免费或固定耗时。

真实回放直接走 GatewayContext → CursorProvider，未经过已打开的 Codex 桌面界面；不能据此宣称桌面完整交互或摘要语义无遗漏。最新窗口验证覆盖失败后续做，未重复消耗额度再跑一次同窗口全冷缓存。安装版 Codex 的协议兼容仍由独立 smoke 覆盖。
